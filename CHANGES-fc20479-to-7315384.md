## 0. Repository shape and mechanical facts

The app is still one HTML file with everything inline (`index.html`, ~35,980
lines), but **it is no longer a strictly single-file app**. Three sibling files
now exist and are load-bearing:

| File | Status | Purpose |
|---|---|---|
| `index.html` | modified | the entire app (markup + CSS + JS, all inline) |
| `manifest.json` | **new** | PWA manifest (was previously a `data:` URI inlined in `<link rel="manifest">`) |
| `sw.js` | **new** | service worker, cache-first |
| `icon.svg` | **new** | PWA icon referenced by the manifest |

### Line endings — read this before editing

Commit `d5cfad4` rewrote the entire `index.html` blob from CRLF to LF **in git
storage**. `core.autocrlf=true` is set, so the *working tree* file is still
CRLF. The raw `git diff` for that commit reports ~70k changed lines; that number
is line-ending noise, not content. To see real changes across this range use:

```
git diff --ignore-space-at-eol fc20479 7315384 -- index.html
```

If you run Prettier on this file, pass `--end-of-line crlf` or you will produce
a 35k-line phantom diff in the working tree.

### Service worker caching gotcha

`sw.js` is cache-first with a hardcoded `CACHE_NAME = "nodrift-v1"` and
precaches `["./", "./index.html", "./manifest.json", "./icon.svg"]`. Because the
fetch handler returns the cached response whenever one exists and never
revalidates, **an edit to `index.html` will not reach a browser that has already
installed the worker until `CACHE_NAME` is bumped** (the `activate` handler
deletes any cache whose name differs from the current constant). Registration
lives at the very bottom of the inline `<script>`, guarded by
`if ("serviceWorker" in navigator)` on the `load` event.

The CSP `<meta>` still allows `manifest-src 'self' data:`; the manifest is now
served from `'self'` rather than the old inline `data:` URI.

## 1. The clock architecture was replaced, not tuned

This is the single largest conceptual change and it **inverts the previous
design**. At `fc20479` the app ran a *dual-clock reconciliation engine* that
cross-checked `Date.now()` against `performance.now()` and rebased every
in-flight timestamp when the two diverged. That engine is gone.

### Deleted symbols (do not reference these — they no longer exist)

```
monoNow()                      CLOCK_HAS_PERF
reconcileSystemClock(reason)   CLOCK_RECONCILE_MAX_GAP_MS
isClockSuspect()               CLOCK_SUSPECT_COOLDOWN_MS
markClockSuspect()             clockSuspectUntilMono
clearClockSuspect()            window.getClockDiagnostics
```

`clockHeartbeat` survives but changed shape: `{ wall, mono }` → `{ wall, lastTick }`.
The persisted legacy field `state.lastHeartbeatMonotonic` is still `delete`d
during `loadState()` as a migration step, but nothing writes it any more.

### The replacement policy (section header `4. SYSTEM CLOCK POLICY`)

The app now **deliberately trusts the host wall clock**, matching how
server-backed trackers behave: if the OS clock jumps, the running timer jumps
with it. The rationale recorded in the source is that a monotonic clock is
frozen while a tab is backgrounded or a phone is locked, so every wake looked
like a clock step and produced a false "system pause" modal. Three defenses
remain, chosen because each is *provable* rather than inferred:

1. **Cross-reload backward steps.** `reconcileClockOnLoad()` scans
   `CLOCK_REBASE_STATE_KEYS` for the newest persisted instant. A witness sitting
   in the *future* cannot be explained by elapsed time, so it proves the clock
   moved backward while the app was closed; `applyClockStep()` rebases by the
   difference. A witness in the past proves nothing and is ignored — the
   asymmetry is intentional.
2. **Segment monotonicity.** `state.activeSegmentFloorSec` /
   `taskState.taskFloorSec` high-water marks still guard a hard process kill
   followed by a backward clock change.
3. **Commit-time arithmetic.** `assertShiftWindow()` (new, see §2) refuses to
   persist a shift whose window is too short to contain its own hours.

`reconcileSystemClock(...)` call sites were all replaced with
`markClockHeartbeat()` — in `tick()`, in the visibility wakeup handler, and in
the lease takeover path. `markClockHeartbeat()` now only stamps
`{ wall, lastTick }` from `Date.now()`.

### Timestamp key lists were split

```js
CLOCK_MEASUREMENT_STATE_KEYS = ["sessionAnchorWall","idleStart","idleWakeup",
                               "lastActivity","lastHeartbeatWall","tabHiddenAt"]
CLOCK_LABEL_STATE_KEYS       = ["loginTimestamp"]
CLOCK_REBASE_STATE_KEYS      = MEASUREMENT.concat(LABEL)   // union, for the witness scan
```

`rebaseTimestampBag(bag, deltaMs, keys)` now takes an explicit key list.
**`applyClockStep()` only rebases the measurement keys; `loginTimestamp` is now
strictly immutable and is never rebased.** It is an absolute label the user
reads, not an anchor any duration is derived from.

`SYNC_INSTANT_KEYS` *does* now include `loginTimestamp`, because a receiving
device must render the same shift start the authoring device did.

### New constants

```js
CLOCK_STEP_THRESHOLD_MS   = 2000    // repurposed: "witness in future by more than this"
SESSION_RESUME_GRACE_MS   = 90000   // NEW: how long the app may be absent and still credit the gap
SHIFT_WINDOW_TOLERANCE_MS = 2000    // NEW: slack for independently-floored work/break seconds
CLOCK_ANOMALY_LOG_LIMIT   = 40      // was 20
CLOCK_ANOMALY_LS_KEY      = "nodrift_clock_anomalies_v1"   // NEW
```

### The anomaly log is now persisted and structured

`recordClockAnomaly()` **changed signature — this is a breaking call-site
change**:

```js
// before
recordClockAnomaly(deltaMs, reason)
// now
recordClockAnomaly({ deltaMs, applied, reason, verdict, proof?, detail?, wallDeltaMs? })
//   verdict ∈ "step" | "gap" | "refused" | "repair"
```

Entries are unshifted, capped at 40, and mirrored to `localStorage` via
`persistClockAnomalies()`; `loadClockAnomalies()` runs from
`reconcileClockOnLoad()`. Every access is try/caught — a storage failure
degrades to an in-memory log and must never break timekeeping. The user-facing
toast now only fires when `verdict === "step" && applied !== 0`, above
`CLOCK_NOTIFY_THRESHOLD_MS`, with a segment actually in flight.

### `getActiveSegmentSeconds` gained a third parameter

```js
getActiveSegmentSeconds(advanceFloor = false, nowMs = null, ignoreFloor = false)
```

`ignoreFloor` bypasses the high-water mark. It exists for boundary events that
measure *as of a deliberately earlier instant* — specifically the idle lock,
which rewinds to the last keystroke. Applying the floor there would hand back
exactly the idle gap the rewind exists to remove. The old
`&& !isClockSuspect()` guard on floor advancement was removed from both this
function and its task counterpart.

## 2. `assertShiftWindow()` — new commit-time invariant

```js
assertShiftWindow(loginTs, logoutTs, workSec, breakSec)
  → { loginTs, logoutTs, workSec, breakSec, untrackedSec, repaired }
```

Rules it enforces:

- a shift cannot end before it starts;
- a window cannot be **shorter** than the tracked time inside it (minus
  `SHIFT_WINDOW_TOLERANCE_MS`);
- a missing endpoint is reconstructed from the other plus the hours;
- **work and break are never recomputed from the window.** Deriving break as
  "window minus work" would convert discarded idle time and paused sessions into
  break time the user never took. Surplus window is surfaced as `untrackedSec`.

`repaired` is a human-readable `"; "`-joined string, or `null`.

Wired into four write paths, with two different failure policies:

| Path | Behaviour on violation |
|---|---|
| `executeSubmit()` (tracked shift) | repairs silently + `console.warn` + warning toast |
| `createShiftLogEntry()` (midnight rollover) | repairs + `console.warn`, no toast (unattended) |
| manual entry (`saveManualEntry`) | **refuses** when the user typed both endpoints — toast: `"<X> of work and break will not fit between <login> and <logout>"` |
| log edit | **refuses** under the same condition (`editHadBothEndpoints`) |

The refusal policy exists because silently moving a logout epoch would leave it
contradicting the logout *string* the user typed, which is what the logbook
renders.

## 3. Boot and session recovery were restructured

`loadState()` is now a **pure read**. It no longer performs rollover, no longer
calls `executeSubmit()`, and no longer runs an idle audit. Previously it could
auto-submit a stale shift straight out of the parse, measuring the in-flight
segment from yesterday's anchor all the way to now — filing an entire night as
work.

Recovery now lives in a new function, ordered explicitly:

```js
async function recoverSessionOnBoot()
```

1. If a live segment exists, compute `lastAlive = max(lastHeartbeatWall,
   tabHiddenAt, lastActivity, sessionAnchorWall)`.
2. If `nowWall - lastAlive > SESSION_RESUME_GRACE_MS` and idle tracking is on →
   `triggerIdleLock(lastAlive, "system")`, handing the unobserved gap to the
   user. If idle tracking is off, credit the wall time (`lastHeartbeatWall = nowWall`).
3. `delete state.tabHiddenAt`.
4. `await checkMidnightReset(new Date(Date.now()))` — this caps each day at its
   own midnight and files one entry per day.
5. Clear a stale `activeDate` if the session produced nothing and the day has
   passed.
6. `saveState(true)`.

**Call-site ordering matters:** it is invoked from the DOM-ready block *inside*
`acquireLease().then(async (owns) => { if (owns !== false && !isTabConflict) ... })`.
The lease is acquired **before** any recovery runs, because recovery writes to
the logbook and a tab that does not own the session must never do that. The old
inline three-branch idle audit that lived in that `.then()` was deleted.

### Visibility-wakeup handler rewritten

```js
const lockAnchor = Math.max(state.tabHiddenAt||0, state.lastHeartbeatWall||0, lastActivity||0);
const observedGapMs = nowWall - lastActivity;
const wasSuspended = Number(state.tabHiddenAt) > 0 ||
                     nowWall - (state.lastHeartbeatWall || nowWall) > SESSION_RESUME_GRACE_MS;
triggerIdleLock(lockAnchor || lastActivity, wasSuspended ? "system" : "inactivity");
return;  // <- now returns
```

A hidden/suspended tab is classified as `"system"`, not `"inactivity"`, which is
what made the system-pause modal copy reachable again.

### Idle-resume anchoring fix

In the idle-resolution handler, where the resumed segment starts now depends on
the user's choice:

```js
const resumeFrom = choice === "discard" ? nowWall : resolutionTime;
```

Work/Break must pick up at `resolutionTime` (the gap was already banked there,
so anchoring later would leave a hole). Discard must anchor at `nowWall` —
`resolutionTime` is when the app *noticed* the user was back, not when they
answered, so a machine that woke at 06:00 and a user who answered at 09:00 used
to have three "discarded" hours counted as work.

`triggerIdleLock` now measures with `getActiveSegmentSeconds(false, timeOfIdleWall, true)`
— the `ignoreFloor` case from §1.

## 4. Timezone: `APP_TZ` is now the law; `DOM.primaryTz` is cosmetic only

New module constant:

```js
const APP_TZ = "America/Los_Angeles";
```

Every `Intl.DateTimeFormat` that stamps or interprets **data** now uses
`APP_TZ`. The `#primary-tz` dropdown is explicitly documented as re-skinning the
wall-clock widget and nothing else. **Any code that reads `DOM.primaryTz.value`
to interpret or stamp data is a bug** — changing a display preference would
silently move existing entries onto a different clock.

Sites converted from `DOM.primaryTz.value || "America/Los_Angeles"` to `APP_TZ`:

- manual-entry time parsing (`parseClockTimeToSeconds` caller) — previously
  stamped manual shifts hours away from automatic ones sitting beside them;
- task CSV export formatter;
- the idle modal's "last active" / "current time" formatters (`cachedIdleTz`);
- the rollover hour formatter.

Also: `checkMidnightReset()` now computes `_cachedCurrentDatePST` via
`getPSTDate()` instead of `pstDateFormatter.format(now)`, so "what day is it"
has exactly one answer. Two answers around midnight on a skewed device could
file a shift against the wrong date.

## 8. Sync, factory reset, and data-loss hardening

Several of these fixed paths where a *local* failure propagated to the *cloud*.

### `Sync` module additions

```js
Sync.forgetEverything()   // clears shadow.log/task, pendingDeletes, cursors,
                          // settingsModifiedWire, dirty, and the sync_meta IDB store
Sync.knownIds(kind, records)  // shadow keys ∪ in-memory record ids
Sync.toWire                   // newly exported
```

`sync_meta` was previously untouched by factory reset. Leaving it behind meant
the next outbox derivation walked hundreds of record ids, found none of them in
the now-empty logbook, read that as "the user deleted all of these", and pushed
a tombstone for the entire history — taking the cloud and every other signed-in
device with it.

### `SyncEngine.wipeRemote()` (new)

Pulls the full history from cursor `0` first so records this device has never
seen are enumerated too, unions them with `Sync.knownIds()`, and pushes
`{ kind, id, payload: null, deleted: true, last_modified }` rows in
`PUSH_BATCH` chunks. Returns the count. Enumeration failure is best-effort
(`console.warn`); push failure is deliberately uncaught so the caller aborts.

### `clearAllData()` is now async and account-aware

- Detects `SyncNet.signedIn`; the confirmation copy now explicitly states that a
  signed-in wipe reaches the cloud and every other device, and tells the user to
  cancel + sign out first if they want a local-only wipe.
- **Cloud goes first**, while the shadow that enumerates it still exists. On
  failure nothing local is touched. Guards on `navigator.onLine`.
- After a successful `wipeRemote()` it calls `SyncNet.signOut()`.
- Then the local sequence, now with `Sync.forgetEverything()` inserted into the
  promise chain and `persistedChunkSignatures.clear()`.
- `clearAllDatabaseStores()` now includes the `sync_meta` object store in its
  transaction store list and clears it.

### Tab-eviction data loss

`flushStateBeforeEviction()` (new, also on `window`) writes `state` straight to
`localStorage[STATE_KEY]`, bypassing the debounce, stamping
`lastHeartbeatWall` and advancing the segment floor first. It is called at
**four** sites, always *before* `isTabConflict = true` — ordering is required,
because `saveState()` returns early once that flag is set.

### Takeover null-check

`loadLogsFromDB()` resolves `null` on read error or timeout. The takeover path
did not check. `cachedLogs` became `null`, the push guard still believed the DB
was healthy, and the sync outbox read "no local records" as "the user deleted
all of them". A slow disk during a tab takeover could empty the cloud. Now:

```js
if (logs === null) { isDatabaseHealthy = false; /* toast + abort */ return; }
```

### Chunk-write correctness (`persistedChunkSignatures`)

New `Map` + `chunkSignature(rows)` (djb2 over
`id|lastModified|workSec|breakSec|loginEpochMs|logoutEpochMs|notes`, prefixed
with row count). A chunk is now written when the caller marked it dirty **or**
when its signature no longer matches what was last persisted. This makes
correctness independent of `dirtyChunks` bookkeeping — a caller that forgot to
name a chunk it moved a record out of used to leave a stale duplicate that
reappeared on the next load. The map is cleared on IDB error, on key-read error,
on takeover, and on factory reset (empty ⇒ full rewrite, the safe default).

## 9. Import / backup / snapshot correctness

### Shift import merges by **record id**, not by calendar date

The old merge resolved whole dates. `"overwrite"` dropped every local shift
sharing a date with the backup, so a Tuesday holding three shifts lost two to a
backup carrying only the morning — and the conflict wizard showed one line for
that day. Now `byId` is a `Map` keyed on record id, ids are minted where absent
(`newLogId()`), and per-record semantics are:

- **not present locally** → added (`logsAddedCount++`)
- **keep-local** → local record untouched
- **keep-both** → incoming gets a fresh id and both survive
- **overwrite** → backup wins *that record only* (`logsOverwrittenCount++`)

Exact-duplicate collapse still runs afterwards for pre-id backups, but the key
now includes `notes` (two shifts with matching times and different notes are two
different shifts) and ties are broken on `lastModified` so the result is
deterministic rather than array-order dependent.

### Task import `"overwrite"` no longer truncates

Previously `cachedTaskLogs = [...data.taskLogs]`, which deleted every task
recorded since the backup was taken. Now merged through a `Map` keyed on id,
minting ids where absent. All three resolution branches run through
`backfillTaskPausedSec()`.

### `triggerAutoSnapshot(preImage)` now snapshots the *pre-mutation* array

Signature changed. The call was moved in `saveLogs()` to **before**
`cachedLogs = logs`, and the pre-mutation array is passed explicitly. The day's
restore point used to be captured after the first change of the day landed, so
the one thing it could never undo was that change — deleting a month at 09:10
created a snapshot containing the deletion. Rows are now shallow-copied
(`source.map(l => ({...l}))`) because the IDB write happens after an `await` and
the live array is mutated in place elsewhere.

## 10. Task record shape changed (two new fields)

### `taskState.startedAtMs`

`startTimeMs` is the anchor of the **current** segment and moves on every
resume, so it cannot answer "when did this task start?". The save path used to
invent a start by subtracting the duration from the end, which put the recorded
start hours after the real one on any task that was ever paused.

`startedAtMs` is set once on start, cleared on reset, and added to both the task
state field list and `TASK_INSTANT_KEYS = ["startTimeMs", "startedAtMs"]` so it
is clock-domain-converted during sync. Save path falls back to the old
derivation only when `startedAtMs` is absent (legacy state), and clamps
`startMs` if the span would be shorter than the duration.

### `task.pausedSec`

Everything inside the span the timer was not running for. Stored, not
display-derived, so `startMs + durationSec + pausedSec === endMs` holds.

- `backfillTaskPausedSec(list)` (new) derives it for legacy records on load;
- `rehydrate("task", r)` in the sync layer derives it for incoming wire records
  (note: `rehydrate` previously early-returned for any non-`"log"` kind — it now
  has a `task` branch);
- the task edit path **recomputes** it rather than carrying it over, since an
  edit may move either endpoint or the duration;
- task CSV gained a `Paused` column (header is now
  `Date,Start,End,Duration,Paused,Notes`);
- the task row meta line appends `" · <X> paused"` when non-zero, so a row no
  longer reads as a contradiction (endpoints an hour apart above a 20-minute
  duration).

## 11. Assorted correctness fixes

| Area | Change |
|---|---|
| **Break-only days** | `createShiftLogEntry()` bailed on `!workSec`; now requires `work > 0 \|\| break > 0`. The midnight loop's `hasAccumulatedWork` became `hasAccumulatedTime` (work + break + any active segment regardless of mode), and both `activeWork > 0` guards became `activeWork > 0 \|\| activeBreak > 0`. A shift that crossed midnight on break used to be discarded. |
| **Midnight-crossing shifts in group headers** | Day-group login/logout selection ordered by `parseTimeToMinutes()` (minutes past midnight). A 22:00→02:00 shift logs out at minute 120, lower than any daytime login, so a header could show a day ending before it began. Now keyed on `loginEpochMs`/`logoutEpochMs` with the minutes parse as legacy fallback. |
| **Weekend work in breakdowns** | Weekend shifts are excluded from targets by design (contracted week is Mon–Fri) but were previously counted *nowhere*, so a Saturday shift appeared in the logbook and heatmap and then rendered as a blank `—` row. Now tracked as `weekendW/weekendB/weekendDays`, the row is no longer treated as empty (`!hasWeekendWork` in `isEmptyBucket`), and a `"N Weekend(s)"` badge with an explanatory `title` is appended to the meta row. The shift count now uses `countedShifts` (weekday shifts that fed the numbers) instead of `bData.logs.length`, which used to read "3 Shifts" above totals derived from one. |
| **CSV goal column** | `exportCSV()` used `resolveGoalSecForDate(l.date)`, which returns the *oldest* goal recorded for that date; a day with two shifts on different targets exported a delta contradicting the screen. Now prefers the shift's own frozen `l.dayGoal`. |
| **Time-adjustment modal** | The whole `deficitSec` mechanism was removed — it shifted `state.loginTimestamp` forward to absorb an over-subtraction, corrupting the shift start. Work subtraction is now capped-and-reported symmetrically with break via `actualSubtractedWorkVal`; previously the shortfall was computed, capped, then never applied, so subtracting 30m from a 10m timer reported "30m subtracted" and lost 20m silently. Toast copy now covers both buckets (`"Production is already 0."`, `"<X> subtracted (Production capped at 0)."`). |
| **Dead code** | `ytdDaysCount` removed (accumulated, never read). |
| **Minor regression to be aware of** | In `executeSubmit()` the epoch computation lost its explicit radix: `parseInt(fullYear, 10)` → `parseInt(fullYear)`. Harmless for the current inputs, but if you touch that block, restore the radix. |
| **Stale doc comment** | `getTaskTotalSeconds()`'s JSDoc (~line 20398) still says *"only while the wall clock is trusted - see isClockSuspect"*. `isClockSuspect` no longer exists. Documentation only; the code is correct. |

## 13. Quick orientation checklist for the next edit

1. Do not reintroduce `performance.now()` for timekeeping. The design is
   documented in the `4. SYSTEM CLOCK POLICY` header block; read it before
   changing anything in that region.
2. Never hardcode `28800`. Call `getStandardDayGoalSec()`.
3. Never read `DOM.primaryTz.value` to interpret or stamp data. Use `APP_TZ`.
4. Any new path that writes a shift must go through `assertShiftWindow()`.
5. Any new path that sets `isTabConflict = true` must call
   `flushStateBeforeEviction()` first.
6. Anything that wipes local data must also clear `sync_meta`, or the outbox
   will tombstone the cloud.
7. `recordClockAnomaly()` takes an object, not `(deltaMs, reason)`.
8. Bump `CACHE_NAME` in `sw.js` when shipping an `index.html` change.
9. Run Prettier with `--end-of-line crlf`.
